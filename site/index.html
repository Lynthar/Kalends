Kalendae — the first day of the Roman month, when accounts fell due. The book they were written in was the calendarium.

Everything with a next date, on one timeline.

Subscriptions, VPS boxes, insurance policies, domains — anything that comes due again. Self-hosted and offline by default: one Rust binary, one SQLite file, no accounts, nothing phoning home.

What it does

Libraries with typed columns, the way a spreadsheet wishes it worked. The column type drives sorting, filtering, and how a cell renders.

Seven templates
Subscriptions, SIM cards, VPS instances, domains, insurance, documents, and a blank one. Add your own columns to any of them.
Two due-date models
Store the next date directly, or store the last renewal plus a cycle and let the engine work it out. Cycles run weekly to three-yearly, plus lifetime and an arbitrary number of days.
Status semantics
Each status value declares whether it counts as spending, whether it should remind you, and whether it belongs on the timeline. A price catalogue you are still comparing stays out of the totals.
Reminders and calendar
Telegram and SMTP on an N-days-ahead threshold plus a daily digest, de-duplicated across restarts and caught up after downtime. An ICS feed for calendar apps.
Money stays put
Prices are recorded in the currency you paid in and totalled per currency. Conversion is a view you can turn on; notifications and ICS never convert.
Backups run themselves
A nightly SQLite snapshot, fourteen kept on a rolling basis, plus a JSONL export of every table that stays readable without Kalends around.

Install

Prebuilt binaries are Linux only — x86-64, aarch64 for ARM boxes and NAS units, and a musl build for old glibc or Alpine. SHA256SUMS ships alongside them.

LinuxDockerFrom source 
# a release binary
tar xzf kalends-<version>-x86_64-unknown-linux-gnu.tar.gz
KALENDS_DATA=./data TZ=Asia/Shanghai ./kalends

# docker — the compose file builds locally, no image is published
docker build -t kalends:local .
docker compose -f deploy/compose.yaml up -d

# from source, serves 127.0.0.1:4180 with data in ./data/
cargo run

Set TZ. Containers default to UTC and “today” ends up wrong. Everything else lives in the settings page.

What it is not

Worth knowing before you install it rather than after.

  • Single user, by design. No accounts, no permissions. The optional PIN keeps a curious housemate out and nothing more.
  • Not meant to face the internet. Put it behind Tailscale or a VPN rather than a public port and a PIN.
  • The database has to be on local disk. SQLite locking over SMB or NFS isn't reliable enough to trust with your only copy.
  • The interface is Chinese only. There's no i18n layer, so the UI and the CLI output are all in Chinese.
  • Search is a plain LIKE. Fine for hundreds of rows; there's no full-text index and no virtual scrolling yet.
